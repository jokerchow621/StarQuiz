# 更深假設的設計實驗與重新驗證

這裡保留三題 9×9 搜尋成果、答案、驗證證書及原始搜尋統計。
棋盤形狀與唯一答案沒有改動；正式題庫的位置與分數已依新模型重新計算。

## 2026-10-12 成組排除修正

現行模型為 `star-group-support-hall-failed-literal-v2`。它把成組排除納入
0 層推理：若 k 個色塊的剩餘候選只占 k 行／列，這些行／列就不能再放
其他色塊的星星。規則對行、列、區域的所有配對與組數都適用，並與既有
相容支持排除反覆執行至固定點；每次假設後也會執行同樣的排除。

| 題目 | 目前正式關卡 | 0～100 分數 | 未四捨五入內部評分 | 現行模型深度 |
| --- | ---: | ---: | ---: | ---: |
| 前一輪候選（`9x9-candidate.json`） | 998 | 97 | 37.690931 | 1 |
| A（`9x9-harder-a.json`） | 974 | 13 | 10.612338 | 0 |
| B（`9x9-harder-b.json`） | 995 | 94 | 36.827868 | 1 |

A 在成組排除後直接解完；另外兩題在 0 層固定點仍未解完，但只需一層
假設。舊模型漏掉這種技巧，將三題都判為兩層，並高估 A、B 的難度。
所有 JSON 的頂層欄位保存現行評分、完整證書與正式關卡位置；舊模型的
證書、分數及當時關卡位置完整保存在 `previousAnalysis`，供比較與追溯。
0 層題的 `shallowerCertificate` 為 `null`，不建立不存在的負一層證書。

0～100 分以現行全部 999 題的未四捨五入 `orderScore` 線性校準：
最低 `6.553634167291669` 對應 0，最高 `38.819468362169026` 對應 100。
先完成成組排除，再按巢狀深度與剩餘推理負擔排序；驗證器工作量仍不等於
玩家最短解法步數。目前全題庫最高已驗證深度是一層，沒有兩層或三層題。

## 原始搜尋紀錄

第一輪在舊模型 `star-group-support-failed-literal-v1` 下，針對當時判為
兩層的題目聯動修改多處區域邊界，測試 3,354 個通過結構驗證的候選，
保存 `9x9-candidate.json`，當時仍未找到完整驗證為三層的題目。

第二輪使用多處邊界演化、平衡區域生長、連通走廊、Hamiltonian 路徑切分、
暫時跨越不連通中間狀態、兩層首輪殘留最大化，以及 8×8 嵌入 9×9，
保存 A、B。當時的題庫整合版本為 `v2026.10.12.2`：B 放在第 998 關、
A 放在第 999 關，並移除當時第 821、822 關；前一輪候選位於第 997 關。
這些是歷史位置，不是目前位置。

完整統計在 `search-2026-10-12.json`。其頂層的 `model`、`baseline`、
`methods` 與 `campaignIntegration` 保留搜尋及匯入時的結果；
`currentRevalidation` 保存新模型的分數與位置。評估次數可能包含重訪，
不能相加稱為不同題目的數量。未找到三層題不代表三層題不存在；舊模型的
兩層判定也不能當成現行模型下需要兩層的證明。

重新驗證全部保存的題目：

```sh
node experimental/verify.js
```
